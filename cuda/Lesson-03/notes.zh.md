# 第 03 课：计算能力

计算能力（Compute Capability，CC）是 GPU 某一代产品的版本号。它决定了你在第 00 课到第 02 课里见过的那些特性和硬件限制，比如线程束和线程块最多 1024 个线程的上限。每个 CUDA 特性都要求一个最低的计算能力。

## 这个数字代表什么

它的格式是 主版本.次版本，比如 Hopper 是 9.0。主版本号变了，表示新一代架构，硬件也是新的。次版本号变了，表示同一代里的一次改版。为 CC 7.0 编译的代码，可以在任何 CC 7.0 或更高的 GPU 上运行。用到 CC 9.0 特性的代码，不能在更老的 GPU 上运行。

## 每个线程束的线程数

线程束是 GPU 一起运行的 32 个线程（第 01 课）。32 这个数字是硬件固定的，也是计算能力规格的一部分。GPU 从来不会调度单个线程，它总是以 32 个线程的完整线程束为单位来调度。

> [!NOTE]
> 从最早的 CUDA GPU（CC 1.0）开始，线程束大小就一直是 32，从来没变过。

## 每个 SM 的线程束和线程

SM 是线程块运行所在的物理处理器（第 02 课）。每个 SM 最多可以容纳 64 个活跃线程束，也就是 2048 个线程。当一些线程束在等待显存时，线程束调度器可以挑选其他线程束来运行。活跃线程束越多，就越常有准备好运行的线程束，执行单元也就越能保持忙碌。

## 线程块大小的上限

在第 02 课里，`<<<1, 2048>>>` 能编译通过，却什么都没启动。原因是线程块最多只能有 1024 个线程，这是计算能力规格里的硬性限制。一个线程块必须放进一个 SM，而 SM 固定的寄存器预算限制了一个线程块能有多大。

## 每个 SM 的 FP32 核心

Pascal、Volta 和 Ampere 每个 SM 有 64 个 FP32 核心。Hopper 和 Blackwell 有 128 个。FP32 核心越多，每个 SM 在每个时钟周期能做的浮点运算就越多。

## 每个 SM 的共享内存

共享内存是每个 SM 内部的高速内存。一个线程块里的所有线程都能使用它。它的容量一代比一代大：

- Pascal：64 KB
- Volta：最高 96 KB
- Ampere：最高 164 KB
- Hopper 和 Blackwell：最高 228 KB

共享内存越大，核函数就能把越多数据留在芯片上，不用去访问全局内存。

## 术语表

- 计算能力（compute capability）：一个版本号（主版本.次版本）。它说明 GPU 支持哪些 CUDA 特性，以及它的硬件限制是多少。
- SM（Streaming Multiprocessor，流式多处理器）：GPU 内部的物理处理器。所有线程都在 SM 上运行。
- 线程束（warp）：GPU 一起调度、一起运行的 32 个线程。
- FP32 核心：每个时钟周期完成一次 32 位浮点运算的硬件单元。
- 共享内存（shared memory）：每个 SM 内部的高速片上内存，由一个线程块里的所有线程共享。比全局（设备端）显存快得多。
- 寄存器文件（register file）：每个 SM 上的一块高速存储，用来存放每个线程的局部变量。表里所有这几代产品，每个 SM 都有 65536 个寄存器。
- CUDA Toolkit 12.8+：为 Blackwell（CC 10.0）编译代码时需要它。
